# 2026-09-23 — Responsive UI bug fixes (portfolio site)

Task: fix responsive-only UI bugs in the React/Vite/Tailwind v4 portfolio, with the
About page called out as the example.

## Layout system (important convention)
Public pages share a fixed two-column shell: a `w-14` (56px) SnakeBar rail + a sidebar
nav, whose total width is meant to line up with the header's brand column so the header's
vertical divider continues down through the page.
- `xl` (1280px)+ : brand `513px` = rail 56 + sidebar `457px`
- `lg` (1024px)  : brand `400px` = rail 56 + sidebar `344px`

If you change the header brand width you MUST change the sidebar width in
`About/SubjectBox`, `Project/FilterBox`, `Blog/index`, `Blog/Post`, `Contact/ContactBox`
to keep them aligned.

## Bugs found (via puppeteer audit, not guessing)
1. **Collapsed mobile menu painted a bordered empty strip.** `.mobile-nav-panel` collapses
   with `max-height:0; overflow:hidden` but kept `border-t` + `border-b`, so it rendered a
   2px-tall bordered box at `top-[55px]`, stacked on the header's own 1px bottom border →
   a ~3px "double border with an empty gap" under the header on every page. This was the
   exact thing the user described.
2. **Header nav broken from 768–957px.** Desktop nav switched on at `md` (768px) but needed
   ~958px (513 brand + 314 links + 131 contact) → `_Contact-me` overlapped `_Project`/`_Blog`
   and `scrollWidth` was 827 > 768.
3. **About sidebar double borders.** The `contacts` h2 had `border-t` which collided with the
   bottom border of whatever sat above it: (a) mobile with `personal-info` collapsed;
   (b) desktop with the `skills` tab active.
4. **Split layouts switched on too early (768px).** About content pane was crushed to 255px
   (text wrapped one word per line, Skills 2-col grid unusable). Same for Project/Blog/Contact.
5. **Footer label wrapped at 320px** ("find-me-in :" broke onto two lines, footer 72px tall).

## Fixes applied (19 files)
- Header + all page shells: `md:` → `lg:` for the split layout; brand `lg:w-[400px] xl:w-[513px]`;
  sidebars `lg:w-[344px] xl:w-[457px]`.
- `mobile-nav-panel`: no border at all, anchored `top-full`; the last list item draws the
  bottom line. Documented in `index.css`.
- About sidebar: removed the `contacts` h2 `border-t`; the last tab (`skills`) owns an
  always-on bottom border at `lg`; the mobile content wrapper (`Bio` variant="mobile") got a
  bottom border so the content/contacts separator survives.
- Project grid: `lg:grid-cols-3` → `xl:grid-cols-3` (2 cols at lg, so cards aren't cramped).
- Footer: tighter base paddings + `whitespace-nowrap` → 58.8px single line at 320px.

## Second pass — deeper audit (parent-overflow detection)
The first audit only checked overflow past the VIEWPORT. A second script (`deep.mjs`) checks
whether any element spills outside its own parent's content box, which catches cramped/
overflowing text. That found two more real bugs:

6. **Contact email overflowed the sidebar at 1024–1200px.** `mohammad12345sadeghi@gmail.com`
   needs 285px; the `lg` sidebar was 344px with `lg:px-10` → only 264px available (21px spill).
   Fixed by widening the `lg` sidebar 344px → 400px (and the header brand 400px → 456px, keeping
   `brand = rail 56 + sidebar`). Now: brand 456 + links 358 + contact 146 = 960 ≤ 1009 at 1024.
7. **Contact code pane squeezed at 1280–1536px.** The longest code line needs 434px of content
   but the pane only gave ~300px, so lines broke mid-token with the continuation at column 0.
   Fixed: `xl:min-w-[420px]` on the pane, tighter xl padding (`xl:pr-8`, `<p>` `xl:px-6`), and
   `xl:whitespace-nowrap` so a code line never breaks — below ~1600px it scrolls horizontally
   instead. From 1600px up every line renders intact.

False positive to ignore: `span.w-1.5.h-1.5.bg-[#00D5BE]` in `BootLoader` uses `animate-ping`
(a transform scale), so its bounding box grows without any layout impact.

Final state: 0 horizontal scroll, 0 nav overlap, 0 panel artifacts, 0 parent spills
(excluding the two false positives above), build passes.

## Third change — BootLoader replaced with a minimal loader
The user did not want the entry animation at all, just a simple loading state.
`src/Components/BootLoader/index.jsx` was a ~200-line cyberpunk boot sequence (terminal HUD
card, fake boot logs, random-step progress %, shimmer, animated glows, cyber grid). It is now
~45 lines: full-screen `#030712`, one CSS spinner (`.loader-spinner` in `index.css`) plus
"Loading..." in the mono font, click-anywhere-to-skip, and a fixed 600ms minimum
(`MIN_VISIBLE_MS`). No fake progress, no logs, no entrance/exit effects.

Also removed the now-dead keyframes `bootBlink`, `bootFadeIn`, `cardIn`, `shimmer` from
`index.css` (verified by grep that nothing else referenced them), and added
`.loader-spinner { animation: none }` to the existing `prefers-reduced-motion` block.

Still untouched on purpose: `PageTransition` (the terminal card shown on every in-app
navigation — `nav://process`, `RUNNING _ABOUT`, 45% bar). The user scoped this request to
"entering the site", so that per-navigation card was left alone; it was verified to still
render correctly after the keyframe cleanup.

Note: `sessionStorage["booted"]` still gates the loader so it only appears once per session.

## Fourth change — Home hero typing animation freeze (deterministic fix)
Symptom reported by the user: on the home page the name with the typing animation sometimes
never appears / locks part-way, and only a refresh fixes it.

Reproduced deterministically, 12/12 runs: intro stopped at `"Hi all|"`, name empty, role never
rendered. Root cause was `typeit-react` under React StrictMode:
- its init effect ends with `instanceRef.current?.updateOptions(opts) || generateNewInstance()`.
  `updateOptions()` returns the instance (always truthy), so the rebuild branch only runs while
  the ref is null. StrictMode mounts → cleanup (`destroy()`, ref still pointing at the dead
  instance) → remounts, reusing the destroyed instance → nothing types, `afterComplete` never
  fires, the whole sequence stalls.
- Using the TypeIt core directly also failed (12/12, with DOUBLED characters — `"MMoohhaamm…"`)
  because the core's `#fire()` loop is `requestAnimationFrame`-driven with no `destroyed`
  guard; `destroy()` only clears `setTimeout` ids, so the StrictMode cycle left a second live
  loop writing into the same element.

Fix: new `src/Components/Typewriter/index.jsx` with **no TypeIt dependency at all** — its own
`setTimeout` chain, one writer per mount, cleanup cancels the timer and clears `textContent`.
API `text / as / speed / lifeLike / cursor / onDone`. `InformationText` now uses it for all
three hero lines. Caret is a `<span class="ti-cursor">` whose `|` comes from CSS `::before`
(added to `index.css`), so `textContent` stays exactly the prop text — the caret is invisible to
copy/paste, screen readers and tests. `typeit-react` was then uninstalled from `package.json`
(no imports remained; bundle was already tree-shaken, so size was unchanged).

Verified: 12/12 cold loads OK, 8/8 remounts after client-side navigation OK (0 console errors),
and 6/6 widths (360/390/768/1024/1280/1920) OK with no horizontal scroll.

## Fifth change — Contact code pane overflow, properly fixed
The third-pass `xl:whitespace-nowrap` fix (item 7 above) was a band-aid: it turned the mid-token
line break into a sideways scroll. Measuring the real line boxes (not `scrollWidth`, which
clamps to `clientWidth` and always reports "fits") showed the longest line needs 458px of
content while the pane offers ~372px at 1280 — a 94px spill.

Replaced the flat `<p>`+`<br>` markup with one flex row per line: a fixed-width line-number
gutter span + a `min-w-0 whitespace-pre-wrap break-words` code cell, driven by a `[text, color]`
token array. `xl:whitespace-nowrap` is gone. Now:
- 320–1920px: 0 spill (13px slack on mobile, 24px on desktop), no scrollbar in the pane
- the longest line wraps INSIDE the code cell, so the continuation aligns under the code
  instead of under the line number
- at 1600px+ nothing wraps at all, so the desktop look is unchanged
Added a stable `.code-preview` class on the pane for auditing.
